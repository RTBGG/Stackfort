F-001 was revalidated on 2026-08-23 with vendor NGINX packages `1.26.3` on
Debian 13, `1.28.3` on Ubuntu 26.04, and `1.26.3` on Rocky Linux 10.2. Every
guest passed syntax-gated activation, a no-op second reconciliation, exact
root-owned configuration permissions, byte-identical loopback-only proxy trust,
unknown-host HTTP close, unknown-SNI TLS rejection, and placement of
`nginx.service` below `stackfort-core.slice`, including boot enablement.

F-002 was validated on the same three guests on 2026-08-23. Each vendor
`nginx -t` accepted a deterministic typed account include containing a static
host, a wildcard 301 redirect, fixed and preserved path/query components, fixed
security headers, and deliberately unknown dollar-prefixed markers in the
user-controlled URL. The latter pass confirms that literal dollars are emitted
as URL data rather than compiled as NGINX variables. The ordinary adversarial
unit suite also passed before the Linux integration binary was cross-built.

F-003 was validated on all three guests on 2026-08-23 through the production
activation implementation. Each guest staged a complete global sites revision,
passed the fixed private-candidate `nginx -t`, atomically promoted it, gracefully
reloaded the service, and passed a local Host-routed HTTP probe. A fresh
activator replayed the same operation without another reload. The test then
constructed an interrupted `promoted` journal and current pointer; a second
fresh activator restored and reloaded the former valid revision, removed only
the interrupted tree, activated a final revision, and left the exact current
symlink with no journal. The harness reported
`NGINXTransactionalActivation=passed` on Debian 13, Ubuntu 26.04, and Rocky
Linux 10.2. The final Ubuntu kernel was `7.0.0-30-generic`; installed NGINX
versions were Debian `1.26.3`, Ubuntu `1.28.3`, and Rocky `1.26.3`.

F-004 was validated on the same three guests on 2026-08-23 through the
production repository, fenced operation runner, host identity/filesystem code,
and NGINX activator. Each guest created an account-owned static file and served
it through the generated host; an effective `0600` mode denied the NGINX worker,
and a symlink to `/etc/passwd` was not served. Exact access/default ACLs used
`www-data` on Debian/Ubuntu and `nginx` on Rocky. Rocky remained SELinux
enforcing with persistent exact `httpd_sys_content_t` rules and bounded
`restorecon`. An edit switched the live host to a custom nested root, then a
second domain served that same shared root; suspend, resume, and logical removal
changed routing while the shared/non-empty root survived removal of one and
then both domains. The harness reported
`StaticDomainLifecycle=passed` on Debian 13, Ubuntu 26.04, and Rocky Linux 10.2.

G-001 was validated on the same guests on 2026-08-23. The production renderer
placed a fixed HTTP-01 location ahead of normal content, canonical-host

`httpd_sys_content_t` rule for the fixed challenge subtree. The harness reported
`ACMEHTTP01Routing=passed` on Debian 13, Ubuntu 26.04, and Rocky Linux 10.2.
